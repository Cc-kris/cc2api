## 2. 结论

模型广场按“公开分组 → 可售模型列表”组织，不按现有“渠道 → 平台 → 分组 → 模型”组织。模型名称和系统基础价格以 `PricingService` 维护的网站模型价格目录为主数据源；该目录优先从 sub2api 的 `price-mirror` 同步，镜像数据来自 LiteLLM，远程同步失败时回退到仓库内置价格文件。渠道与账号不负责生成网站主模型目录，只负责把目录筛选成当前分组真正可售的模型。

本方案采用以下固定口径：

1. 左侧只显示状态为启用且 `is_exclusive=false` 的公开分组，按分组 `sort_order` 排序。
2. 右侧模型主目录来自网站已同步的系统模型价格目录，并按照分组平台提取对应模型；OpenAI 分组中的 GPT 系列模型由系统目录的 `openai` provider 数据产生。系统目录读取失败时，仅当当前启用渠道对该平台提供完整销售定价的模型集合，才允许使用这组完整渠道定价作为临时目录；部分或混合渠道定价不得掩盖系统目录故障。
3. 右侧最终列表只显示同时满足系统目录存在、至少存在一条有效账号路由、能够完成真实计费且价格可解析的模型；只有分组关联启用渠道并开启模型限制时，才额外应用渠道模型白名单。
4. 渠道是可选处理层，不是模型广场前置条件，也不再作为主模型枚举源。渠道中的模型限制、模型映射、计费模型来源和渠道价格覆盖是四项独立能力，只有已配置或已启用的能力才参与计算。模型映射完成后，模型广场必须使用最终上游模型进行账号可路由校验，并按照与真实调度相同的 `billing_model_source` 口径执行限制判断。
5. 账号用于验证模型是否可路由，并在渠道采用“按上游模型计费”时确定计费模型，不直接生成模型名称或提供客户售价。
6. 渠道显式配置、且具有完整渠道价格的站点自定义模型可以作为网站目录扩展项；没有完整价格的渠道别名只参与映射，不单独形成模型列表行。
7. 客户原价是应用分组倍率前的系统计费价；倍率价是原价乘以当前用户在该分组的有效倍率。
8. 账号 `rate_multiplier` 只影响账号成本统计，不进入倍率价计算，模型广场不返回该字段。
9. 当前用户存在分组专属倍率时，倍率价使用专属倍率；否则使用分组默认倍率。页面同时标明默认倍率和当前有效倍率。
10. `fast` 价格复用实际 `service_tier=priority` 计费规则，不在前端使用固定倍数猜算。
11. 客户售价在账号调度前按“客户模型 + 分组”确定；账号数量、命中的账号和账号上游模型只影响成本与盈亏，不改变模型广场原价或倍率价。

该口径保证模型广场展示结果与真实请求路径、真实计费路径一致，不泄露账号、渠道和上游凭证信息。

### 3.2 当前缺口

| 缺口 | 影响 |
|---|---|
| 页面以渠道为主视角 | 客户不能先选择公开分组，再查看该分组价格 |
| 当前客户接口的模型集合主要由渠道配置推导 | 系统已同步的 GPT、Claude、Gemini 等网站模型不能自动成为模型广场主目录，未关联渠道的分组也缺少完整展示路径 |
| 平台到价格目录 provider 的映射位于管理端 Handler | 客户模型广场无法直接复用统一的平台目录查询能力 |
| 系统目录、可选渠道配置与账号能力尚未形成统一查询 | 直接展示系统全量目录会包含当前分组无法承接的模型 |
| 当前接口只返回单套基础价格 | 不能同时展示原价和倍率价 |
| 用户专属倍率由前端另行拼接 | 容易出现展示倍率与实际计费倍率不一致 |
| 当前 DTO 不包含 Fast 价格 | 无法展示 `service_tier=priority` 的实际价格 |
| 现有 `billing_model_source=upstream` 会把账号路由带入客户扣费 | 客户收入与上游成本混在同一模型口径，导致同一模型、同一分组的客户售价不稳定 |
| 当前页面会展示专属分组 | 不符合本次“只展示公开分组”的范围 |

## 4. 业务范围

### 4.1 页面主流程

1. 已登录客户进入“模型广场”。
2. 左侧加载所有启用的公开分组，显示分组名称、平台、默认倍率、当前有效倍率和模型数量。
3. 默认选中排序第一的公开分组。
4. 客户点击分组，后端先从网站模型价格目录提取该平台模型；分组存在启用渠道时应用该渠道实际启用的配置，不存在启用渠道时跳过渠道层；最后通过账号路由能力过滤并展示模型列表。
5. 模型列表按行展示模型名称、计费方式、标准价格、倍率后价格和 Fast 价格。
6. 客户输入模型名搜索时，只过滤当前分组的模型列表。
7. 当前分组无可售模型时，页面展示明确空状态，不回退到其他分组。

### 4.2 模型列表字段

| 字段 | 展示规则 |
|---|---|
| 模型名称 | 始终显示客户请求时使用的模型名 |
| 计费方式 | 显示按 Token、按次、按图片或按秒 |
| 输入价格 | Token 计费时，在同一单元格显示输入原始单位价和倍率后输入单位价 |
| 输出价格 | Token 计费时，在同一单元格显示输出原始单位价和倍率后输出单位价 |
| 缓存读取价格 | 在同一单元格显示缓存读取原始单位价和倍率后单位价；值为 `null` 时不显示；明确配置为 `0` 时显示免费 |
| 缓存写入价格 | 在同一单元格显示缓存写入原始单位价和倍率后单位价；值为 `null` 时不显示；明确配置为 `0` 时显示免费 |
| Fast 价格 | Fast 可用时分别显示输入、输出、缓存读取、缓存写入的原始单位价和倍率后单位价；不可用时整块不显示 |
| 阶梯价格 | 存在上下文区间或规格层级时显示可展开的阶梯价格 |

“原价”不是一个独立汇总字段，也不是输入、输出、缓存价格之和。模型广场没有单次请求的 Token 用量，无法计算请求总额，因此每个价格单元格只展示对应计费项的倍率前单位价与倍率后单位价：

```text
输入列：原价 $2.00 / 1M tokens    倍率价 $2.40 / 1M tokens
输出列：原价 $8.00 / 1M tokens    倍率价 $9.60 / 1M tokens
缓存读：原价 $0.20 / 1M tokens    倍率价 $0.24 / 1M tokens
缓存写：原价 $2.50 / 1M tokens    倍率价 $3.00 / 1M tokens
```

按次模型显示“每次原价 / 每次倍率价”，图片模型显示“每张原价 / 每张倍率价”，按秒模型显示“每秒原价 / 每秒倍率价”。

### 4.3 不在本次范围内

- 不在模型广场展示账号名称、账号 ID、账号倍率、账号余额、账号状态或上游地址。
- 不在模型广场展示渠道名称、渠道 ID、内部模型映射链或内部计费模型名。
- 不新增模型收藏、模型对比、在线试用和直接创建 API Key。
- 不修改真实请求调度和真实扣费规则。
- 不把瞬时限流、短时过载作为模型目录上下架依据；实时状态继续由“渠道状态”页面承载。
- 不新增数据库表和数据库迁移。

## 5. 核心数据关系

```text
sub2api price-mirror / LiteLLM ──► PricingService 网站模型价格目录
                                               │
公开分组 ── 分组平台 ──► platform/provider 映射 ──► 平台模型候选集
   │                                           │
   │ 可选关联 0..1                             ▼
   ├────────► 启用渠道 ── 模型限制/映射/覆盖价处理
   │                                           │
   ▼                                           ▼
分组绑定账号 ── 账号平台/模型映射 ─────────► 可路由模型集合
                                               │
                                               ▼
                              客户模型固定原价解析
                                               │
                                               ▼
                              原价 × 当前有效分组倍率 = 倍率价

实际命中账号 ── 实际上游模型/上游用量/账号成本倍率 ──► 财务成本与盈亏
```

系统模型价格目录负责“网站有哪些标准模型及其基础价格”。渠道是可选层，按配置分别承担模型限制、模型映射、计费模型选择和价格覆盖；分组没有启用渠道时整个渠道层跳过，存在渠道但没有启用或配置某项能力时仅跳过对应能力。账号负责“当前分组实际上能否路由该模型”。现有渠道约束保证一个分组最多属于一个渠道，因此每个模型在每个分组下只有一套固定原价和倍率价。账号间的上游价格差异进入财务成本，不进入客户售价。

## 6. 模型可用性提取规则

### 6.1 公开分组

分组同时满足以下条件才进入左侧列表：

- `status=active`
- `is_exclusive=false`
- 未软删除

公开订阅分组同样进入列表。模型广场是公开商品目录，不以当前用户是否已经订阅作为隐藏条件。

### 6.2 客户侧候选模型

候选模型先由网站模型价格目录产生，再应用渠道扩展与限制，处理顺序固定为：

1. 将分组平台映射到价格目录 provider：`openai → openai`、`anthropic → anthropic`、`gemini → google`、`antigravity → anthropic`；
2. 通过 `PricingService.ListModelNamesByProvider` 读取该 provider 的全部系统模型名；
3. 分组存在启用渠道时，将渠道中显式配置且具有完整渠道价格的站点自定义模型加入候选集；没有启用渠道时跳过本步骤；
4. 分组存在启用渠道且渠道 `restrict_models=true` 时，候选集只保留渠道定价表中存在模型条目的客户请求模型；没有启用渠道或 `restrict_models=false` 时不使用渠道定价表过滤候选集；
5. 分组存在启用渠道时，渠道精确映射和通配符映射只转换模型路由与计费名称，不替代网站主目录；
6. 按 `platform + lowercase(model_name)` 去重，并按模型名称升序排序。

“完整渠道价格”的判定与计费模式一致：Token 模式至少能够解析输入价和输出价；按次、图片、按秒模式至少存在默认单价或有效阶梯价格。缓存价格和 Fast 价格仍为可选字段，不作为自定义模型进入目录的前置条件。

账号的空模型映射表示“允许当前平台的全部模型”。由于候选集已经由网站模型价格目录限定为有限集合，空映射不会再产生无限目录。账号仍只负责校验候选模型是否可路由，不直接枚举模型广场。

### 6.3 渠道规则的准确口径

“渠道规则”是四项相互独立的可选配置，不等同于渠道定价：

| 渠道字段 | 作用 | 未配置或未启用时的处理 |
|---|---|---|
| `restrict_models` | 控制是否限制当前分组可使用的模型 | 为 `false` 时不缩减系统模型目录 |
| `model_mapping` | 将客户请求模型映射为渠道目标模型 | 没有命中时继续使用原模型名 |
| `billing_model_source` | 整改后只决定账号成本归集使用的模型，不改变客户模型广场和客户扣费售价 | 使用渠道实体已经归一化的默认值 `channel_mapped` |
| `model_pricing` | 可选价格覆盖；`restrict_models=true` 时同时充当模型白名单 | 没有价格条目且未启用模型限制时，完整使用系统价格 |

分组没有关联启用渠道时，渠道层整体跳过，等价于：`restrict_models=false`、无模型映射、按客户请求模型取系统价格、无渠道价格覆盖。该分组仍然进入模型广场，并通过系统目录、分组账号和分组倍率形成完整模型列表。

分组没有渠道，或者存在渠道但不使用渠道定价时，处理链固定为：

```text
系统模型目录与系统价格
        │
        ├─ 无启用渠道或 restrict_models=false：不做渠道模型过滤
        ├─ model_mapping 未命中：模型名保持不变
        ├─ model_pricing 无条目：不做渠道价格覆盖
        ▼
账号可路由校验 → 系统原价 × 分组倍率 = 倍率价
```

因此，渠道定价不是模型广场的必填数据。只有以下三种情况依赖渠道定价：

1. `restrict_models=true`，渠道定价表承担模型白名单；
2. 系统目录外的站点自定义模型需要完整渠道价格；
3. 管理员需要覆盖系统价格或使用按次、图片、按秒、阶梯等渠道计费方式。

当系统模型目录暂时不可用时，模型广场只允许从当前启用渠道中选取具有完整销售定价的模型作为临时目录。包含部分覆盖、缺少必需销售字段或只有限制名单的渠道定价，均不足以替代系统目录；此时接口必须保留目录错误，不能返回不完整的价格列表。

### 6.4 账号可路由校验

每个候选模型必须至少命中一个目录有效账号。目录有效账号口径为：

- 账号绑定当前分组；
- 账号状态为启用；
- `schedulable=true`；
- 未达到自动停用的过期时间；
- 账号平台符合分组原生调度或现有混合调度规则；
- 如果渠道命中模型映射，先将客户模型解析为最终上游模型，再使用该模型执行可路由校验；
- 渠道限制判断使用与真实网关一致的计费模型来源：`requested` 使用客户请求模型，`channel_mapped` 使用映射后的上游模型；
- 账号模型映射支持客户请求模型；
- 分组存在启用渠道且开启模型限制时，渠道模型白名单允许该计费模型。

目录校验不读取短时限流、临时过载和模型临时冷却状态，避免模型列表行随瞬时运行状态频繁消失。请求发起时仍由现有调度器执行完整实时校验。

账号校验逻辑从现有调度筛选中提取为无副作用的共享判定函数，模型广场与真实调度复用同一套平台、混合调度、模型映射和渠道限制规则，不复制另一套近似逻辑。

模型广场直接复用现有账号、账号分组绑定、账号模型映射、账号上游地址和渠道配置，不要求管理员重复录入账号或上游。客户请求模型广场时不调用上游账号的 `/models` 接口，不读取或返回账号密钥；网站标准模型目录由 `PricingService` 的价格镜像同步任务维护，账号侧模型同步继续是管理端显式操作。

### 6.5 模型剔除条件

出现任一情况时，该候选模型不进入模型列表：

- 模型既不存在于对应平台的系统模型价格目录，也不是具有完整渠道价格的站点自定义模型；
- 没有目录有效账号支持该模型；
- 渠道限制拒绝该模型；
- 计费模型无法确定；
- 标准价格无法通过真实价格解析链得到；
- 计费模式字段不完整，无法形成对应单位价格。

## 7. 价格提取与计算规则

### 7.1 三类倍率的严格边界

| 倍率 | 数据位置 | 用途 | 是否进入模型广场倍率价 |
|---|---|---|---|
| 分组默认倍率 | `groups.rate_multiplier` | 默认客户售价倍率 | 是 |
| 用户分组专属倍率 | `user_group_rate_multipliers.rate_multiplier` | 覆盖该用户在该分组的客户售价倍率 | 是，优先于默认倍率 |
| 账号倍率 | `accounts.rate_multiplier` | 上游成本和账号统计口径 | 否 |

有效倍率公式：

```text
effective_multiplier = user_group_multiplier ?? group.rate_multiplier
multiplier_price       = original_price × effective_multiplier
```

页面左侧显示：

- 无用户专属倍率：`倍率 1.2×`
- 有用户专属倍率：`我的倍率 1.1×`，并在次要信息显示`默认 1.2×`

### 7.2 计费模型确定

模型广场和客户实际扣费统一使用固定的客户售价模型，售价在账号调度前确定：

```text
sale_model = 模型广场当前行的客户请求模型名
```

渠道对该客户模型配置价格时，渠道价格覆盖系统价格；没有渠道价格时，直接读取 `sale_model` 的系统价格。账号模型映射和账号实际命中的上游模型不参与客户售价解析。

渠道 `billing_model_source` 的边界调整为：

| 用途 | 是否使用 `billing_model_source` |
|---|---|
| 客户模型广场原价 | 否，固定按 `sale_model` 解析 |
| 客户实际扣费 | 否，与模型广场使用同一固定售价快照 |
| 账号上游成本归集 | 是，用于确定真实上游成本模型 |
| 财务盈亏报表 | 是，用于计算每次请求的实际上游成本 |

现有计费链中依赖 `upstream` 结果决定客户扣费模型的路径必须同步整改为“客户收入固定、账号成本按实际路由变化”。否则同一模型、同一分组会因随机命中不同账号而产生不同客户扣费，模型广场无法提供可信价格。

### 7.3 标准价格来源优先级

模型广场所称“原价”，严格定义为当前模型、当前分组在应用分组倍率之前的客户销售单位价。它不是上游账号成本价，也不是一次请求的预计总价。

价格复用 `ModelPricingResolver` 的真实解析顺序：

1. 当前分组关联启用渠道时，该渠道的模型定价；
2. 系统模型价格数据；
3. 系统本地回退价格；
4. 无可用价格时判定为不可售。

系统目录读取失败不等同于普通价格字段缺失。只有启用渠道对同一平台返回完整销售定价的模型集合时，才允许以该集合构造临时目录；渠道价格不完整或混合时必须继续返回系统目录错误。

因此，未配置渠道价格时，“原价”就是网站系统模型目录同步的输入、输出、缓存读取、缓存写入或 Fast 单位价；配置渠道价格覆盖时，“原价”就是该分组实际采用的倍率前渠道单位价。无论来自系统目录还是渠道覆盖，乘分组倍率之前都称为原价。

模型名称来源与价格覆盖来源严格分离：系统模型目录负责默认模型名称和默认基础价格；渠道价格只覆盖实际计费字段，不把渠道配置重新定义为网站主模型目录。OpenAI 分组中的 GPT 系列在没有渠道覆盖价时，直接使用系统同步价格作为原价。整个分组没有配置渠道定价时，同样使用系统价格，不影响模型广场展示。

渠道价格允许按字段覆盖。未覆盖字段继续使用系统模型价，因此接口返回价格来源枚举：

- `channel`：全部展示字段来自渠道；
- `system`：全部展示字段来自系统价格；
- `mixed`：渠道覆盖部分字段，其他字段来自系统价格。

前端只展示“渠道定价”或“系统定价”这类通用标签，不返回内部渠道和账号信息。

### 7.4 Token 价格

Token 计费统一以系统内部每 Token 单价计算，接口同时返回标准化的每百万 Token 数值供前端直接展示：

```text
display_price_per_1m = price_per_token × 1,000,000
```

每个价格字段使用相同结构：

```json
{
  "original": 2.5,
  "multiplier_price": 3.0,
  "unit": "per_1m_tokens"
}
```

模型广场展示的是单位价格，不是某一次请求的总消费。每个模型分别展示输入、输出、缓存读取、缓存写入和 Fast 单位价格。

标准 Token 请求的实际总消费公式为：

```text
original_total =
    input_tokens       × original_input_per_token
  + output_tokens      × original_output_per_token
  + cache_read_tokens  × original_cache_read_per_token
  + cache_write_tokens × original_cache_write_per_token

multiplier_total = original_total × effective_multiplier
```

等价地，每个客户单位价先计算为 `customer_unit_price = original_unit_price × effective_multiplier`，再分别乘对应 Token 数量后求和。两种算法必须使用相同内部精度，结果一致。

Fast 请求使用 Fast 输入、输出、缓存读取和缓存写入单位价格替换标准单位价格后执行同一公式，不把标准价格与 Fast 价格重复相加。

### 7.5 Fast 价格

Fast 对应请求中的 `service_tier=priority`。价格投影与 `BillingService.computeTokenBreakdown` 使用同一套纯函数，规则为：

1. 存在官方或系统 Priority 输入价时，Fast 输入使用该价格；否则使用实际计费函数的回退结果。
2. 存在 Priority 输出价时，Fast 输出使用该价格；否则使用实际计费函数的回退结果。
3. 存在 Priority 缓存读取价时，Fast 缓存读取使用该价格；否则使用实际计费函数的回退结果。
4. 缓存写入严格复用真实计费函数当前规则，不单独假设翻倍。
5. 渠道覆盖价、系统价、阶梯价均先完成标准价格解析，再进入 Fast 投影。
6. 只有至少一个有效账号路径允许 `priority` 且模型具备 Fast 能力时才返回 Fast 价格。
7. 按次、按图片、按秒计费不显示 Fast。

为防止展示价和扣费价漂移，实施时先从现有计费函数中抽取“标准/priority 单位价格解析”纯函数，再由真实计费和模型广场共同调用。不得在模型广场服务或前端复制一套 `2×` 计算。

### 7.6 阶梯、按次、图片和按秒价格

| 计费模式 | 列表展示 |
|---|---|
| Token | 默认输入/输出/缓存价格；存在上下文区间时展示区间明细 |
| 按次 | 默认每次价格；存在层级时展示每个层级价格 |
| 图片 | 默认每张价格；存在分辨率层级时展示 1K/2K/4K 等价格 |
| 按秒 | 默认每秒价格；存在层级时展示层级价格 |

每个默认价和阶梯价均返回固定的原价与倍率价。上下文阶梯、图片规格和请求层级是明确的价格档位，不是由多个账号产生的最小值至最大值范围。

### 7.7 缺失值和零价格

- `null` 表示系统没有该价格，前端不渲染该行。
- `0` 表示明确免费，前端显示 `$0`。
- 后端不得用“非零才返回”的旧展示逻辑处理模型广场价格。
- 价格计算保留系统内部精度，前端只在显示层格式化，不把格式化结果用于后续计算。

- 真实上游模型名和模型映射链
- 内部价格表 ID、区间 ID、排序内部字段

### 8.3 服务职责

新增 `ModelSquareService`，职责固定为：

1. 批量读取启用公开分组；
2. 批量读取分组可选关联的启用渠道；
3. 批量读取分组目录有效账号；
4. 按分组平台从 `PricingService` 读取网站模型候选集；
5. 合并具有完整价格的站点自定义模型并应用渠道限制与映射；
6. 复用调度能力判定筛选账号路径；
7. 按客户模型和分组解析唯一固定原价；
8. 应用当前用户有效分组倍率生成固定倍率价；
9. 输出客户字段白名单。

Handler 只负责登录身份、功能开关、调用服务和统一错误响应，不承载价格或账号聚合逻辑。

### 8.4 查询与性能

新增账号仓储批量查询 `ListCatalogEligibleByGroupIDs`，一次返回所有公开分组的目录有效账号及分组绑定关系，避免逐分组查询产生 N+1。

单次请求查询结构：

1. 活跃公开分组查询；
2. 渠道、渠道分组、渠道模型定价和区间批量查询；
3. 目录有效账号与账号分组批量查询；
4. 当前用户分组专属倍率批量查询。

网站模型与价格直接读取 `PricingService` 的内存快照，不在每次客户请求时访问 GitHub、LiteLLM 或上游账号。价格文件和渠道缓存继续复用现有内存数据。首版不新增跨用户响应缓存，避免用户专属倍率串价。接口支持客户端取消信号，所有查询沿用请求上下文。

### 8.5 价格计算复用

从现有计费代码抽取只读纯函数，输入为：

- 已解析模型价格；
- 计费模式；
- 上下文区间或层级；
- `service_tier`；
- 分组有效倍率。

输出为标准单位价与倍率后单位价。真实扣费和模型广场共同调用该函数。抽取前先补齐现有 Fast、渠道覆盖、缓存和区间计费回归测试，抽取后要求测试结果完全一致。

## 13. 风险、兼容性和回滚

| 风险 | 控制措施 |
|---|---|
| 网站目录与渠道配置口径再次混用 | `PricingService` 负责系统目录；渠道的限制、映射、计费模型来源和价格覆盖分别判断，未启用的能力不参与计算 |
| 把渠道误设为模型广场前置条件 | 渠道按 0..1 可选关联处理；无启用渠道时复用真实请求链的系统价格与账号调度路径 |
| 平台与 LiteLLM provider 映射漂移 | 映射统一收口到 PricingService，管理端同步与客户模型广场共用并覆盖单元测试 |
| 价格镜像临时不可用 | 复用现有内置价格文件回退，不在客户请求链路实时访问外网 |
| 展示价与扣费价漂移 | 真实扣费与模型广场共用单位价格解析函数 |
| 账号与渠道重复判断产生差异 | 抽取无副作用能力判定并由调度与模型广场共用 |
| 现有 upstream 计费导致客户售价随账号变化 | 客户收入改为调度前按客户模型和分组固定；实际上游模型只用于成本与盈亏计算 |
| 用户专属倍率串价 | 后端按当前用户计算，不做跨用户响应缓存 |
| 空 mapping 产生无限模型 | 只从有限的系统模型价格目录枚举，账号空 mapping 仅表示允许该有限集合 |
| 短时限流导致列表行闪烁 | 目录不使用瞬时限流和临时过载作为上下架依据 |
| 敏感内部结构泄漏 | 独立客户 DTO、字段白名单和序列化测试 |
| 旧链接失效 | `/available-channels` 保留重定向 |
| 新功能异常影响客户 | 复用现有功能开关，可立即隐藏入口并让接口返回空数组 |

回滚顺序：

1. 关闭 `available_channels_enabled`，立即隐藏客户入口并停止返回模型目录；
2. 回滚前端模型广场路由和页面；
3. 回滚新接口、聚合服务和账号批量查询；
4. 保留原有渠道、账号和计费数据，不需要数据库回滚；
5. 价格纯函数抽取只有在完整计费回归测试通过时保留，否则随版本一并回滚。

## 14. 完成标准

满足以下全部条件后，本功能才算完成：

- 客户侧存在可通过功能开关控制的“模型广场”入口；
- 左侧只显示启用的公开分组及正确倍率；
- 右侧标准模型名称来自网站同步的系统模型价格目录，OpenAI 分组中的 GPT 系列来自 `openai` provider；
- 没有关联启用渠道的公开分组仍能按照系统模型目录、账号能力和分组倍率展示；
- 未配置渠道定价且 `restrict_models=false` 的分组能够直接展示系统模型与系统价格；
- 启用渠道模型限制的分组经过渠道定价白名单和账号能力双重校验，不展示当前分组无法路由的系统目录模型；
- 桌面端按统一价格列展示，移动端使用可展开纵向列表，不使用模型卡片；
- 原价、倍率价、缓存价、Fast 价和阶梯价与真实计费规则一致；
- 模型广场与客户实际扣费均在账号调度前按客户模型和分组确定固定售价；
- 多账号、账号映射和实际上游模型变化不改变客户售价，只改变财务成本；
- 输入、输出、缓存读取、缓存写入和 Fast 的单位价格与总消费公式全部有测试；
- 账号倍率不进入客户售价；
- API 不泄露账号、渠道、上游和凭证信息；
- 后端测试、前端测试、类型检查、lint、生产构建和页面交互验证全部通过；
- 发布流程完成并验证 Release 产物后停止，不执行未授权的手工生产升级。
