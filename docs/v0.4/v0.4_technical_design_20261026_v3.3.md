### 2.2 R10 AI 创作多配置（沿用现有 JSON，不建表）

**唯一存储**：扩展现有 `data/content_ai_provider.json`，不创建 `content_ai_models` 或其他数据库表。结构升级为：

```json
{
  "version": 2,
  "revision": 1,
  "default_config_id": "cfg_01",
  "default_model": "model-a",
  "configs": [{
    "id": "cfg_01", "label": "生产默认", "provider": "openai",

```

- `configs` 允许同 provider 多条；`default_config_id + default_model` 必须指向同一配置内存在的模型，全系统只有这一项默认。空配置时二者均为空。
- 启动读取旧单配置 JSON 后先备份为 `content_ai_provider.v1.bak`，在内存映射为 v2 并原子写回；保留原 provider/base_url/key/models/default 语义，迁移幂等。读取/写入失败不得覆盖原文件，启动日志报错且 AI 功能返回明确错误。
- 进程内所有写操作使用同一 mutex；按 `revision` 做乐观并发校验，不匹配返回 `409 config_revision_conflict`。写临时文件→`fsync`→同目录 `rename`→目录 `fsync`，权限 `0600`；多副本部署不支持共享本地文件配置，本期单实例部署并在方案中明示。
- Key 使用内容域专用 AES-256-GCM 工具加密，密钥读取已有 `TOTP_ENCRYPTION_KEY` 配置；**不得导入已 Deprecated 的 `internal/payment.Encrypt/Decrypt`**。未配置密钥时禁止新增/替换 Key 并返回 `503 encryption_not_configured`；旧明文仅在首次成功加密迁移后淘汰。日志、响应和错误中永不输出明文 Key。

**API（统一前缀 `/api/v1/admin/content/articles/ai-config`）**：

| 方法/路径 | 请求要点 | 成功响应/语义 |
|---|---|---|
| GET（基路径） | 无 | `{version,revision,default_config_id,default_model,configs[]}`；配置仅含 `api_key_masked`，绝无真实/加密 Key |
| POST `/configs` | `{revision,label,provider,base_url,api_key,models}` | 201 + 新配置；Key 必填，ID 服务端生成 |
| PUT `/configs/:id` | `{revision,label,provider,base_url,api_key,models}` | 200 + 更新配置；空串或接口刚返回的掩码均保留旧 Key |
| DELETE `/configs/:id` | `If-Match: "<revision>"` | 204；默认或排队/执行中任务引用返回 `409 model_in_use` |
| PUT `/configs/:id/default` | `{revision,model}` | 200；同一 mutex 内校验并切换，保留其他配置 |

### 2.6 R8 分页：SSR/公开 API 统一 20 条
- `ListArticles`/`ListNews` 支持 `locale=<lang>&fallback=zh`：一次查询合并（译文优先，无译文回退中文），`total` 是回落合并后的全部主内容数，不是译文条数；删除前端跨 locale 窗口合并后切片。
- `GET /api/v1/public/articles|news?locale=<lang>&page=1&page_size=20` 与 SSR 共用同一 service。省略 `page_size` 时默认 **20**；前台页面与 SSR 永远传 20。为兼容既有 API 调用，显式 `page_size=1..100` 仍有效，>100/非数字返回 `400 invalid_page_size`。

- 301 的 `Location` 保留 locale、筛选和排序查询，仅替换 page/page_size；page 写入规范 URL（第 1 页可省略），刷新/分享保持一致。

### 2.8 埋点事件（R11，唯一契约）
- 每次详情页浏览生成 UUID `view_id`；`page_view/content_impression/content_click/content_read/heartbeat/page_leave` 都在 `payload` 携带同一 `view_id`、内容 ID/类型、locale 和位置代码。`session_hash` 跨页面保持，UV 仍按现有访客口径去重。
- 停留时长只写 `duration_ms`（整数毫秒），不使用 `read_seconds`。heartbeat 每 15 秒上报当前累计值，page_leave 上报最终累计值；有效范围 `0..14400000`（4 小时），非法/递减值丢弃。聚合按 `view_id` 取最大有效值，避免心跳求和、重复 beacon 和跨会话重复计数；无 page_leave 时最后一个 heartbeat 仍纳入。
- `content_read` 在同一 view 停留首次达到 10 秒时只记一次；曝光按 view+content+position 去重，点击保留次数；CTR=点击数/曝光数，曝光为 0 时返回 0 而非除零。
- referrer 保存 `referrer_host`，分类规则为直接/搜索引擎/社交/外链；筛选时区 Asia/Shanghai。
- 上报用 sendBeacon / fetch keepalive，不阻塞页面；失败静默且不重试风暴。迁移 219 的 payload 白名单只新增 `duration_ms`、`view_id` 所需键。

## 3. URL 与 SSR 路由（按 v3.2 三项决策定死）

### 3.1 URL 矩阵（决策①中文带 /zh；决策②前缀式）

| 首页 | `/<lang>/` | `/` → `/zh/` |

> 注：现有 SSR 详情路由已是 `/articles/:locale/:slug`、`/news/:locale/:slug`，**天然兼容**；**要新增的是列表/首页的前缀路由 + 旧写法 301 路由**。

**SSR 语言与 SEO 统一规则**：带前缀页面以 URL 语言为准；无前缀 `/`、`/news`、`/articles` 只返回 301 `/zh/...`，不得读取 cookie 渲染其他语言。已发布译文存在时该页 self-canonical + `index,follow`，hreflang 只含中文和已发布译文，`x-default` 指中文；无译文回落中文时 canonical 指中文版 + `noindex,follow`，该语言不进 hreflang/sitemap。例如有效 `/articles/en/x` canonical 为 `/articles/en/x`；无德文译文的 `/articles/de/x` canonical 为 `/articles/zh/x`。标签全部在服务端原始 HTML 输出。

### 3.2 P10 根因（更正 V1，补 N13 中间件层）
**不是** SSR locale 匹配 bug。404 有**两层**原因，缺一不可修：
1. **路由层**：前后端都没有 `/:locale/news`、`/:locale/articles` 这类列表路由 → 新增前缀路由 + 旧写法 301 路由。
2. **嵌入中间件层（N13，V2 漏掉的关键层）**：`server/frontend_embed.go:17` 全局 `r.Use(web.ServeEmbeddedFrontend())`，**先于** Gin 路由执行；只有 `isPublicSSRRoute`（`web/embed_on.go:358-366`）命中的路径才 `c.Next()` 放行到 Gin 路由。现有白名单只有 `/`、`/news`、`/articles`、`/docs`、`/robots.txt`、`/sitemap.xml` 及 `/news/*`、`/articles/*`、`/docs/*` 前缀。**`/en/news`、`/zh/articles`、`/en/` 等新前缀路径会被中间件拦截落进 SPA 分支**（再由 `isPublicFrontendRoute` 判为非公开页跳登录），只在 Gin 侧加路由修不好。
   - **修法**：`isPublicSSRRoute` 增加 `/{lang}/`、`/{lang}/news`、`/{lang}/articles`、`/{lang}/news/*`、`/{lang}/articles/*` 前缀判断（lang 白名单 en/zh/ru/fr/de）；不在白名单的 `/:locale/...`（如 `/xx/news`）由 handler 返回 **404**（已实测 `/:locale/news` 与现有路由可共存不 panic，但需在 handler 做 locale 白名单校验）。
   - **T1-3 改动位置必须包含** `backend/internal/web/embed_on.go` + `backend/internal/server/routes/public_content.go` 两处。
P10 归属 **P0**（拆出 T1-3）。

### 3.3 SEO + locale 映射（更正 V1；N12 新增映射表）

| URL 段 | 库内 locale（规范化） | 说明 |
|---|---|---|
| `zh` | `zh-CN` | 主语言 |
| `en` | `en-US` | |
| `ru` | `ru-RU` | |
| `fr` | `fr-FR` | |
| `de` | `de-DE` | |

- **读方向映射**：扩展 `public_content_service.go:351 normalizePublicLocale`——URL 段 → 规范 locale（含上表映射 + 白名单校验，不在 en/zh/ru/fr/de 内返回错误 → handler 404）。新闻侧 `findPublishedNews`（`public_content_service.go:234`）已有 zh/zh-CN 别名解析，统一收编到该函数。
- **写入方向（R3-H4，V3 漏掉）**：`domain/content.go:221 contentLocaleAliases` 目前**只有 zh/en 别名，没有 ru/fr/de** → 必须补 `ru→ru-RU`、`fr→fr-FR`、`de→de-DE`（及小写/下划线变体）。翻译入队时（文章 `content_article_admin.go:135` 请求体 `TargetLocale` 字段 / `:887` 赋给 `task.Language`、新闻侧新路由）统一过 `NormalizeContentLocale` 规范化——否则前端传短码 `ru` 会原样入库，SSR 按 `ru-RU` 查不到。
- **反向映射（库内码 → URL 短码）**：在 `domain/content.go` 新增函数：
  ```go

  func ContentLocaleToURLSegment(locale string) string { /* 先 NormalizeContentLocale 再查反向表 */ }
  ```
  调用点（全部改用它输出短码）：
  - sitemap：`handler/public_content_handler.go:206` 改为 `publicContentPath(prefix, ContentLocaleToURLSegment(entry.Locale), entry.Slug)`；
  - hreflang/canonical 输出：同调 `ContentLocaleToURLSegment`；
  - 长码 URL 301 目标：重定向时调它生成短码路径。
  （现状：`publicContentPath`（`handler/public_content_renderer.go:480`，TrimRight + url.PathEscape 拼接）直接把 `entry.Locale` 拼进路径，输出 `zh-CN` 长码，与 URL 矩阵 `/articles/zh/x` 不一致。）
- **存量数据**：zh/en 已入库为规范码（`content_news_worker.go:918-922`），无需迁移；库内已存在的非白名单 locale（如 `ja-JP`）译文**不出现在前台/sitemap**，保留不删。
- **长码 URL 取舍（对齐 TC R9-07/R12-05）**：`zh-CN`/`en-US` 等长码**不进** `isPublicSSRRoute` 白名单（白名单只放短码）；访问 `/articles/zh-CN/x` 由 handler **301 到短码版** `/articles/zh/x`。

**SEO（sitemap 规则不变）**：
- `sitemap.xml` **只列有译文的版本**；无译文的页面**不进 sitemap**。
- 无译文却在 `/articles/de/x` 显示中文原文时：该页 `<meta name="robots" content="noindex">` + `<link rel="canonical" href="/articles/zh/x">`，hreflang **不列**该语言。
- 有译文的版本：canonical 指向自身，hreflang 列全部已有语言版本。

### 3.4 SSR 渲染现状（N11 更正 V2 的错误描述）
**V2 说"当前未读 content_translations"是错的**。核实 `backend/internal/repository/public_content_repo.go` 现状：
- **文章侧已有译文链路**：列表（L117 附近）、sitemap（L176-200）、详情 `GetPublishedArticle`（L211-271）都已读文章译文，且按**译文自己的 slug** 查询，`publishedArticleTranslation` 还校验 `source_version`。
- **新闻侧没有**：`GetPublishedNews`（L58）不读译文（T9-5 的真实工作量在这）。

**因此本期工作是"补全 + 统一"，不是从零**：
1. 新闻侧补译文读取（复用文章侧模式）。
2. 统一 slug 规则（见 §3.5）——现状"译文 slug 独立"与 URL 矩阵"同 slug"假设冲突，必须收敛。
3. service 层补「无译文回退中文 + 标记 `fallback=zh`」供 noindex/canonical 判断。
- 缓存复用 `content_public_cache.go`（现有）+ Redis 限流；**失效时机**：内容发布/更新、精选变更、翻译发布时主动失效对应键。

### 3.5 译文 slug 规则（N11 定死）
- **URL 里的 slug 一律用主语言（中文）原文的 slug**，各语言版本共享同一 slug（`/articles/zh/x`、`/articles/en/x` 同 slug `x`）。
- **解析**：按 `slug` 找到主语言内容 → 按 `(content_type, content_id, locale)` 查译文；有译文渲染译文，无译文渲染中文原文并标 `fallback=zh`。
- **跨语言对应**：靠 `content_id` 关联反查（不靠 slug 匹配）。
- **存量译文 slug 独立的数据**：保留库里独立 slug 不动，但对外 URL/canonical/hreflang 统一用主语言 slug；渲染时按 content_id 反查，不按译文 slug 匹配。
